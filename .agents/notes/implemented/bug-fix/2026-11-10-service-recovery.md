# Agent Note: 无障碍连接恢复与悬浮面板故障诊断

Status: implemented

## Problem

用户反馈后台返回后翻译面板无法唤出，应用仍显示权限开启，Shizuku 加固无法恢复，也缺少重启入口。系统登记为已启用、服务实际连接、面板窗口可用是三个不同状态，旧界面只根据前两者的部分信息判断工作状态。尚无用户手机故障发生时的日志，修复依据是代码中可以确认的恢复和异常处理缺口，以及模拟器复现。

代码中的窗口更新异常被吞掉，连接存活标志仅在销毁时清理；网络回调和隐私拦截器的非 IOException 可逃逸到 OkHttp 调度线程，导致进程退出；Shizuku UserService 启动无回调时会无限等待。早期恢复补丁还存在重启失败仍报告成功、恢复时覆盖其他服务的新设置、用近期事件静默推断服务故障的问题。

## Decision

首页分别展示暂停、系统开关关闭、正在恢复、服务未连接、运行异常和服务已连接。读取系统无障碍总开关及本应用登记项，通过服务连接与 serviceInfo 确认绑定，通过故障状态报告窗口和输入监听异常。ContentObserver 监听系统设置变化，onUnbind 和 onDestroy 均清理运行状态。事件静默不作为故障依据，因为前台静止时可以没有新的无障碍事件。

「重启服务」优先使用已有 WRITE_SECURE_SETTINGS，移除本应用登记项，等待 500 ms 后重新读取当前名单并加回本应用。写入串行化且检查返回值；移除操作部分写入后失败、或重启等待中断时仍执行恢复，随后传播失败或中断。界面最多等待 5 秒确认新的连接序号，写入成功不能单独作为重启成功依据。打开应用时允许自动恢复断开的服务，自动重启设进程级 60 秒冷却。

未获得自动恢复授权时，可以用 Shizuku 授权，或者重建已连接服务的完整运行环境：取消旧任务、销毁窗口和 TTS、清理输入节点与短时上下文，再重新建立翻译流水线和监听。界面始终提供系统无障碍设置入口，允许手动关闭后开启服务。

窗口添加失败会释放旧 ComposeView 并以新视图重试一次；更新位置失败、窗口被系统移除都会使挂载状态失效并报告异常。只记录异常类型，不把窗口异常消息写入日志。面板使用 TYPE_ACCESSIBILITY_OVERLAY，授权依据是无障碍连接；厂商后台弹出开关没有统一查询接口，设置页将其列为需要手动核对的项目。

Shizuku 命令调用设 35 秒超时，连接断开、空绑定和取消均释放连接；命令进程合并标准输出与错误输出，25 秒后终止。加固命令汇总各步骤退出码，仅发送当前 Android 版本支持的权限命令。加固结果和服务恢复结果分别判断，避免一个成功掩盖另一个失败。

网络响应的读取、错误响应读取和关闭操作都在异常捕获范围内，失败交给翻译流处理。隐私规则读取或检查失败转为 IOException 并阻断请求，避免异步调度线程崩溃，也避免失败后跳过隐私检查。[隐私脱敏设计](../feature/2026-11-08-privacy-masking.md)继续定义遮盖和还原契约。

诊断只在设备保留最近 40 条固定格式服务事件，以及最近一次崩溃的异常类型、有限栈帧和主线程标志。异常消息和线程名称可能包含业务数据，因此不保存。复制报告时附设备型号、版本和当前授权状态。崩溃记录使用同步 commit，使进程退出前尽量完成落盘；其他事件使用 apply。服务曾经成功连接后才发送断连提醒，每次断连最多一次。

## Alternatives considered

- 只修改 Shizuku 加固命令：可以改善后台授权，但无法处理已授权却未绑定、窗口失效或翻译监听协程退出，因此增加独立重启路径。
- 根据最后一次事件时间自动重启：可发现事件链断流，但正常静止页面也没有事件，会产生误判；采用绑定检查和明确异常，保留人工重启入口。
- 把 Settings.canDrawOverlays 当作面板权限：标准 API 易于显示开关，但本项目使用无障碍悬浮层，这个开关不能反映实际授权；采用窗口操作结果与厂商设置入口。
- 仅重建 ComposeView：开销较小，但已退出的翻译或设置监听协程仍然失效；本地恢复重建整个运行环境。
- 记录完整异常消息：更便于排错，但请求、译文或隐私条目可能出现在消息里；保留类型和调用栈，用独立用户反馈补充场景。

## Testing

- 执行 `gradlew.bat :app:testDebugUnitTest :app:assembleRelease :app:lintDebug --offline --console=plain`：49 项测试全部通过，Release APK 构建成功，Lint 0 错误、13 警告及 4 条信息提示。同步崩溃落盘产生的 2 条 ApplySharedPref 警告符合上述设计；其余为依赖版本、目标版本、现有清单与资源等提示。
- 新增 12 项回归测试：重启保留等待期间其他服务的改动、拒绝写入、部分写入失败后的恢复、取消后的恢复、短组件名去重，以及流读取/错误响应读取/响应关闭失败、隐私规则读取失败和检查失败时阻断传输。
- Android 12 / API 31 模拟器：手动重启产生停止与重新连接记录，原有其他无障碍服务保持开启；在首页关闭本应用的系统登记项，首页立即显示「无障碍被关闭了」；Shizuku 授权后重新连接成功；强行停止后重新打开可自动恢复，并显示恢复提示。
- 最终 Release APK 覆盖安装后，在系统设置搜索框输入虚构测试文本，截图和 dumpsys window 均确认 TYPE_ACCESSIBILITY_OVERLAY 窗口；回到应用首页后该窗口收起。
- 测试使用 adb 截图及 dumpsys，不用会临时抑制其他无障碍服务的默认 uiautomator dump。厂商后台弹出限制及长时间锁屏后的表现由用户在其手机验证；再次故障时可复制本机诊断。

## Consequences

用户可以看到开关关闭和服务断连的区别，并独立恢复面板及输入监听。重建会清空本次输入状态、在途翻译与内存上下文，返回编辑器后继续打字可触发新翻译。系统调度的后台巡检周期至少 15 分钟，强行停止后的恢复从重新打开应用开始；开关被自动重新开启时保留首页提示。

诊断增加了有限的本机持久记录及可读的应用调用栈。已有自动恢复授权可在 Shizuku 等待前先恢复连接；无授权且系统拒绝绑定时需要系统设置操作。厂商若静默拦截窗口而不返回错误，需要结合该设备的权限页面和诊断进一步定位。
