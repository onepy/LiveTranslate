# Agent Note: 段落翻译与安全范围替换

Status: implemented

## Problem

输入框获得焦点即翻译已有全文，笔记场景容易误发送大量旧文字；整框替换会覆盖未翻译内容。旧请求在下一次防抖期间仍显示结果，用户无法判断替换是否完成。

## Decision

自动模式只在文本变化时提交光标所在行段，单纯获得焦点不提交。段落按 CR/LF 分隔，保留边界空白。显式长按模式优先使用选区；原有非空选区事件兼容触发继续保留，因此只选择文字也可能触发此模式。

范围携带完整原文快照及 UTF-16 起止索引。替换前必须核对当前焦点节点、窗口、原文快照、结果来源与请求完成状态；全文任意部分变化均拒绝旧结果；结果带错误（含[隐私脱敏](../feature/2026-11-08-privacy-masking.md)校验未通过）时同样拒绝。SET_TEXT 写回拼接后的全文；粘贴降级必须确认范围选择成功，禁止未确认就全选粘贴。无法安全替换时只复制译文。

新提交立即清除旧结果并取消旧流，防抖发生在可取消的请求内部。替换成功清除目标和面板并显示“已替换”，后续自身文本事件不重新翻译。首屏预览也在替换后收起。

## Alternatives considered

- 只翻译新增字符：发送范围最小，但输入法组合、回删和插入会导致不完整语句，采用当前段落。
- 保留旧译文直到新请求启动：视觉更连续，但会误导替换操作，改为立即作废。
- 自动重定位旧片段：能容忍其他段落变动，但重复文本和异步编辑可能定位错误，采用完整快照严格核验。

## Testing

范围单测覆盖选区、段落、空段、CRLF、表情 UTF-16、增删差异与快照失效；流水线单测覆盖提交即清除旧结果、取消、防抖、缓存和重试。真实第三方编辑器行为仍需用户验证；本次不在微信或 QQ 中自动输入或替换。

## Consequences

旧笔记不再因点击即被翻译，替换保留范围外文字。代价是没有光标且无法推断编辑位置的控件不自动翻译；无换行的长段落仍按整段处理，不推测句子边界。多行选区允许显式翻译。无聊天页面采集或 OCR；可选内存历史由[短时上下文](../feature/2026-11-08-short-context-word-meanings.md)定义，不改变本篇替换条件。

## Note audit

修改前检索未发现现有活跃笔记，因此没有需要吸收、互链或归档的旧决定。
