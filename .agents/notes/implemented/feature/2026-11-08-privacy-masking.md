# Agent Note: 隐私脱敏：随机代号遮盖与本机还原

Status: implemented

## Problem

应用公开后，用户输入的姓名、公司、地址、证件号、手机号会原样发给第三方翻译源；短时上下文、自定义风格、单词释义也会把原文或还原后的译文带出设备。用户需要一份本地名单，命中的内容绝不离开设备，同时翻译和一键替换照常可用。流式输出会把占位符切成几片，边打边译会在词没打完时就发出前缀，这两点都可能让隐私外露。

## Decision

开启「发送前脱敏」（默认开）时，`Providers.create` 返回 `MaskingTranslator`，它包住真正的翻译源。每次请求，`PrivacyMask.create` 在当前段落、短时上下文和风格文本里找出隐私片段，换成随机代号再交给翻译源；流水线缓存和替换前的核对只接触原文与还原后的译文。

- **匹配**（`PrivacyRules.spans`）：先逐字符折叠（全角转半角、`U+3000` 转空格、`Char.lowercaseChar()`），长度保持 1:1，下标直接用于原文，从不使用 NFKC 或 `String.lowercase()`。名单词至少 2 个字；中文按子串匹配；首或尾是拉丁字母或数字的词，要求该侧相邻字符不是拉丁字母或数字；词内的空格匹配任意空白。别名及其去空格、空格换撇号的写法也是匹配键，覆盖输入法把拼音直接写进输入框的情况。内置规则：邮箱、身份证（格式 + 日期 + 校验位）、6 位以上数字串（允许单个空格或连字符分组），手机号和银行卡号由数字串规则覆盖。所有命中按位置排序，重叠或相邻的片段合并成一段，避免另一个词的尾巴以明文发出。
- **边打边译的前缀**：实时模式下，`InputWatcherService` 把光标相对段落的偏移经 `TranslationPipeline.submit(caret)` 传到 `PipelineConfig.caret`。光标前紧挨着的数字串一律遮住；光标前若是某个名单词的真前缀（中文 1 个字起，拉丁字母 2 个起，且前面不是字母），也临时遮住。长按模式不传光标。`caret` 不进缓存键。
- **代号**：每个代号是 3 个辅音大写字母加 1 个 2–9 的数字（如 `ZQX7`），用 `SecureRandom` 按请求生成。同一请求内的代号两两至少 3 位不同，且不能出现在原文里。同一个值在段落和上下文里共用一个代号。
- **流式还原**（`PrivacyMask.restore`）：翻译源每次发出的是累积全文。在折叠后的文本上找出完整代号（三个字母加一个数字，前面不紧跟字母，后面不紧跟数字），先整体替换，再隐藏末尾仍是某个代号前缀的 1–3 个字母；这个顺序不能反过来。还原中文值时，去掉模型在代号两侧加的空格，除非另一侧是拉丁字母或数字。名单项有别名时译文显示别名。
- **结束校验**（`PrivacyMask.verify`）：段落里的每个代号必须出现 1 次到发送次数之间；只出现在上下文或风格里的代号最多 1 次；不能出现符合代号字母表、但不是用户自己输入的陌生代号。不通过时抛出 `TranslateException`。流水线把它记为错误，面板的「替换」按钮在 `error != null` 时禁用，`InputWatcherService.replace` 也拒绝执行，复制仍可用。
- **兜底**（`PrivacyGuard`）：`Http.client` 的应用拦截器在请求发出前解码查询参数、表单值、JSON 字符串（含 `\/` 转义）和 HTML 实体。只要任一处还含名单词，就抛出 `PrivacyBlockedException`，请求不发出。拦截器不跑内置规则，因为豆包 URL 里固定的 18 位 `tea_uuid` 会被数字规则误判。
  - 规则读取或检查异常时同样阻断请求，并转为 IOException 交给翻译流处理，避免异常逃逸导致服务进程退出；详见[无障碍连接恢复与故障诊断](../bug-fix/2026-11-10-service-recovery.md)。
- **单词模式**：面板对还原后的译文再跑一遍 `spans`，落在隐私片段里的单词点击后既不朗读也不查释义；`WordMeanings.load` 遇到隐私词同样拒绝。面板标题栏显示「已脱敏 N 处」，N 不含光标前缀的临时遮盖。
- **存储**：总开关和三条内置规则开关存为明文布尔值。名单编码成 JSON 后用 `SecretBox`（Android Keystore AES-GCM）加密，存为 `privacy_enc`，同时记录 `privacy_count`；只有名单变化时才重新加密。解密失败时名单会加载为空，`SettingsStore.privacyListLost` 让设置页提示「名单解密失败，已清空」。`Providers.cacheKey` 包含 `PrivacyRules.fingerprint()`，名单或开关一变，旧译文缓存就失效。名单或开关变化也会清空短时上下文。

## Alternatives considered

- **编号占位符 `⟦1⟧` / `[1]` / `{{1}}` / `__P1__`** — 最强理由：格式直观，编号好还原。否决原因：实测哔哩模型只保留 46–92%，最常见的失败是把句首占位符当成省略的主语删掉；translateHtml 会把 `{{1}}` 改写成英文短语。随机代号在所有实测组合里保留 100%，而且没有顺序含义，模型不会去改号。
- **Unicode 私有区字符** — 最强理由：一个字符就够，不会被切开，也不会和正常文字冲突。否决原因：机器翻译只保留 17–54%，gtx 还会把不同的 ID 改成同一个。
- **HTML `notranslate` 标签** — 最强理由：Edge 和 translateHtml 原生支持「不翻译」标记。否决原因：标签里同样只能放代号，没有额外收益；Edge 在 HTML 模式下丢了约 25% 的标签，而且这种做法只适用于部分翻译源。
- **在拦截器里改写请求做脱敏** — 最强理由：一处改动就能覆盖所有出口。否决原因：拦截器看不到流式还原需要的映射，也看不出哪段文字属于哪个提示词。拦截器只做最后一道检查，脱敏放在 Translator 外层。
- **译文回来后按名单把风险词换成星号** — 用户明确不需要；风险内容交给翻译源自己限制。

## Consequences

- **收益**：名单内容、邮箱、证件号和长数字串不会出现在任何发往翻译源的请求里，包括短时上下文、风格提示和单词释义；代号每次请求都换，翻译源无法跨请求关联同一个人。代号被模型弄丢、重复或抄错时，检查不通过并禁用替换，不会把错的值写回输入框。
- **代价与已知上限**：
  - 被遮住的内容模型看不到，性别、单复数、人名还是地名可能译不准；别名不会随俄语等语言变格。
  - 只遮字面内容，「我老婆 ZQX7」这样的关系信息仍会发出。
  - 边打边译时最多漏出 1 个汉字、1 个字母或 5 位以内的数字；输入法把拼音直接写进输入框时，只能靠别名变体覆盖。
  - 朗读和复制使用还原后的译文：在线朗读引擎、输入法云剪贴板不在保护范围内，设置页有说明。
  - 名单词如果和固定的翻译指令或模型名重名，拦截器会挡住每一次请求，这时需要用户改名单。
  - 出现以下信号时需要重新评估本方案：某个翻译源经常让检查不通过（代号格式需要按源调整）；用户需要语义层面的去识别。

## Verification

- `app/src/test/java/com/livetranslate/PrivacyMaskTest.kt` 覆盖：折叠保持长度、全角与大小写匹配、拉丁词边界、重叠合并、三条内置规则（含身份证校验位）、光标前缀遮盖、代号两两差异与不出现在原文、还原与别名、中文两侧空格、流式残片隐藏、缺失代号与陌生代号判失败、用户自己输入的代号形文字不误判，以及 `MaskingTranslator` 在逐字切片的流里不露出代号、翻译源收到的文本和风格不含名单词。拦截器的 JSON、表单、HTML 解码也在其中。
- 运行：`./gradlew :app:testDebugUnitTest`。
- 代号格式的实测（2026-11-08，101 次真实请求，只用虚构文本，覆盖微软 Edge、谷歌 gtx、translateHtml、哔哩加或不加指令，中译英、中译日、中译俄、英译中）：随机代号在所有组合里保留 100%；哔哩流式输出中每个多字符代号都被切进 2 个以上分片，约 23% 的累积快照以残片结尾；按「先还原再隐藏残片」的顺序回放 1707 个快照，残片外露 0 次。豆包和自定义 AI 需要登录或 Key，没有实测；每种组合只有 8 句。
- 真机仍需验证：输入法把拼音写进输入框时的表现，以及各翻译源对代号的长期稳定性。
