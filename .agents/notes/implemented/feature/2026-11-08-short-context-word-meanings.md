# Agent Note: 短时上下文与按需词义

Status: implemented

## Problem

连续段落缺少主语时独立翻译会误判。用户希望学习译文词义，但不接受拖慢主翻译或引入聊天记录采集。

## Decision

短时上下文默认关闭，仅哔哩与自定义 AI 支持。只在第三方输入框替换成功后记入原文，最近三条合计不超过 500 个 UTF-16 单元，仅内存保存。替换后的五秒内首次真实编辑冻结上一轮历史；冻结后的草稿没有停顿超时，用户思考多久都保留。超时只在下一稿开始时判断。切换已观察到的应用或编辑器、关闭功能、修改源/语言、手动清空会清除历史。输入框节点被第三方复用时不能保证识别聊天对象变化，时间策略不是身份验证。

历史作为明确标记的参考数据加入 AI 指令，当前段落仍作为独立用户消息；仅要求返回当前译文，不根据行数切割输出。流水线缓存包含历史列表，工厂使用请求快照。上下文指令属于最佳努力，不能保证模型不误输出。首屏预览不积累历史。

单词展开才触发独立词义请求，当前译文完成后分析；只提交当前原文和译文，不携带历史。自定义源复用其 Chat/Responses 配置，其余源使用哔哩。原文不可点读，译文单词和短语可点读，中文释义不点读。切换内容取消旧协程，词义结果限 32 对内存缓存，词组必须按顺序出现在译文中；失败允许重试。

## Alternatives considered

- 编辑时三十秒超时：能限制滞留，但会打断用户长时间思考，用户明确否决，不采用。
- 读取聊天树或 OCR：能拿到对方消息，但扩大隐私、兼容与耗时范围，不采用。
- 词义与主翻译一次生成：少一次请求，但影响主译文延迟和返回契约，采用点击后异步分析。

## Testing

假时钟测试覆盖五秒起笔、无限编辑停顿、成功提交、三条/五百字约束、清空；流水线测试验证历史改变重新请求、相同历史命中缓存。Android 服务事件与模型输出仍需真机验证，不自动操作聊天软件。

## Consequences

只上传用户主动确认的少量历史，主翻译不等待词义。代价为额外词义请求费用与等待，且释义可能不准确。历史不持久化、不备份；内存缓存中的词义和译文在进程退出时消失。开启[隐私脱敏](./2026-11-08-privacy-masking.md)时，历史与当前段落一同遮盖后才发送，单词模式拒查落在隐私片段里的词。
